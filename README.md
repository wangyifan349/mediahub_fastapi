# MediaHub

MediaHub 是一个基于 **FastAPI + Bootstrap 5 + SQLite + SQLAlchemy + Jinja2** 开发的轻量级图片 / 视频分享平台。项目强调简单、直观和易于二次开发，后端主要逻辑集中在 `main.py`，没有额外拆分大量 Service、Manager、Repository 等层，适合学习 FastAPI、个人部署、小型社区以及媒体分享类项目继续扩展。

## 快速部署

已经安装 Python 的情况下，复制下面的命令即可完成下载、进入项目目录、安装依赖并启动：

```bash
git clone https://github.com/wangyifan349/mediahub_fastapi.git
cd mediahub_fastapi
pip install -r requirements.txt
python main.py
```

启动成功后访问：

- 本机：`http://127.0.0.1:8000`
- 局域网：`http://你的电脑局域网IP:8000`

Windows 用户也可以在第一次执行 `pip install -r requirements.txt` 安装依赖后，直接双击项目中的 `启动.bat` 启动。

> 如果你的 GitHub 仓库最终使用了其他名称，只需要把上面 `mediahub_fastapi` 替换成实际仓库名即可。

## 项目介绍

MediaHub 提供从账号注册、媒体上传、在线播放、下载、评论，到用户主页、作品管理和管理员管理的一套完整基础流程。界面采用宽屏媒体社区布局，首页以作品内容为核心，视频详情页提供大播放器，顶部提供实时搜索，用户可以方便地管理自己上传的视频和图片。

项目目前适合作为一个可以直接运行的媒体社区基础版，也可以继续扩展点赞、收藏、关注、弹幕、视频封面、推荐算法、对象存储等功能。

## 主要功能

### 用户与账号

- 用户注册、登录和退出。
- 登录 / 注册页面采用居中卡片布局，兼顾桌面端和手机端。
- 密码不主动设置最短或最长长度限制。
- 密码使用 PBKDF2-SHA256 哈希保存，不保存明文密码。
- 用户拥有个人主页，可以查看自己的公开作品和相关统计。
- 管理员可以查看用户列表、作品数量、评论数量、注册时间和账号角色。

### 图片与视频

- 支持上传图片和视频。
- 图片格式：JPG、JPEG、PNG、GIF、WebP。
- 视频格式：MP4、WebM、MOV、M4V。
- 默认单文件最大 1 GiB。
- 图片可以直接在线预览。
- 视频可以直接在浏览器中播放。
- 上传文件使用随机文件名保存，避免直接使用用户原始文件名作为磁盘文件名。

### 作品展示与管理

- 首页采用宽屏作品流展示公开内容。
- 用户可以进入“我的作品 / 创作中心”统一管理自己上传的内容。
- 每个作品提供简洁的小型管理按钮。
- 支持一键 **隐藏 / 重新显示** 自己的作品。
- 支持永久删除自己的作品。
- 支持下载原始媒体文件。
- 显示作品浏览次数和下载次数。
- 隐藏后的作品不会继续出现在首页、搜索结果和普通用户可访问页面中。
- 作者本人和管理员仍可以查看和管理隐藏作品。

### 实时搜索

- 顶部搜索栏支持输入时实时刷新结果。
- 可以同时搜索视频 / 图片作品和用户。
- 作品标题、作者名和用户名会计算最长公共子序列（LCS）匹配长度。
- 搜索结果按照 LCS 匹配程度降序排列，让相似度更高的内容优先显示。
- 按回车进入完整搜索页后继续使用相同的排序逻辑。

### 评论

- 登录用户可以在作品详情页发表评论。
- 用户可以删除自己的评论。
- 作品作者可以管理自己作品下的评论。
- 管理员可以删除任意评论。

### 下载

- 首页作品卡可以直接进入下载。
- 作品详情页提供下载入口。
- 创作中心提供下载入口。
- 下载原始文件时自动记录下载次数。

### 权限与基础安全

- 普通用户只能修改或删除自己的作品。
- 管理员可以管理平台中的作品和评论。
- 包含 CSRF 防护。
- 包含登录状态和作品所有权检查。
- 包含媒体访问权限检查。
- 包含上传文件扩展名和媒体类型限制。
- 隐藏作品的媒体文件同样经过后端权限检查，并不是只在前端隐藏。

## 界面特点

- 整体采用更接近现代视频社区的宽屏布局。
- 顶部导航栏采用较薄设计，减少对内容区域的占用。
- 首页优先展示作品，而不是使用过大的宣传区域。
- 视频详情页采用大播放器 + 推荐作品布局。
- 创作中心集中展示作品数量、公开作品、总浏览量和总下载量。
- 用户个人主页包含横幅、头像、作品和数据统计。
- 登录 / 注册页面保持居中、简洁，避免表单和字体过于拥挤。
- 自定义主题颜色尽量遵循 RGB 中 B（蓝色通道）= 0 的设计要求。
- 支持桌面端和移动端自适应显示。

## 启动方式

项目在 `main.py` 中已经直接配置 Uvicorn，因此不需要额外输入复杂的 Uvicorn 启动参数：

```bash
python main.py
```

默认配置：

```text
Host: 0.0.0.0
Port: 8000
Reload: False
```

如果需要修改端口，直接修改 `main.py` 最下面 `uvicorn.run()` 中的 `port=8000` 即可。

## 管理员账号

管理员功能是可选的。第一次启动项目之前，可以通过环境变量指定管理员账号。

PowerShell 示例：

```powershell
$env:MEDIAHUB_ADMIN_USER="admin"
$env:MEDIAHUB_ADMIN_PASSWORD="ChangeMe123!"
$env:MEDIAHUB_SECRET_KEY="请替换为足够长的随机字符串"
python main.py
```

程序只会在数据库中不存在同名用户时自动创建管理员。如果已经存在相同用户名的普通用户，程序不会自动将其提升为管理员。

## 数据保存位置

SQLite 数据库默认保存在：

```text
media.db
```

上传的图片保存在：

```text
uploads/images/
```

上传的视频保存在：

```text
uploads/videos/
```

删除作品时会同时删除对应数据库记录和媒体文件。隐藏作品则只改变展示状态，不删除原始文件。

## 代码设计

这个项目刻意保持较直接的 FastAPI 写法。数据库连接、SQLAlchemy 模型、密码处理和主要路由集中在 `main.py`，普通查询、权限判断和业务处理尽量直接写在对应路由中。

项目不会为了形式上的分层额外加入大量 Service、Manager、Repository 或复杂类。只有数据库 Session、当前用户、CSRF、密码哈希、媒体路径、LCS 等确实需要重复使用的基础逻辑才保留为小函数，方便阅读和修改。

当前版本可以直接用于本地运行、局域网使用、学习和二次开发。如果需要长期公开部署到互联网，建议至少增加 HTTPS、反向代理、严格的文件内容检测、上传限速、内容审核和独立对象存储，并根据访问量将 SQLite 替换为 PostgreSQL 或 MySQL。
